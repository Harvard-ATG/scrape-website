Scrape Update Walkthrough

How the scraper refreshes a site today, how an update run would work differently, and what the taxonomy, rules and tooling in PR #10 add.

StatusThe rules and tests are reference code. The --update flag itself is not wired into the scraper yet.

Today

A refresh crawls a site by following links from a seed URL. Whatever the crawl reaches is saved. Whatever it misses is treated as gone.

With update

The sitemap says which pages exist and when each last changed. An update run fetches only what is new or changed, and checks before it retires anything.

This PR

Combines the earlier scraper work and adds a taxonomy, 20 rules, a tested reference implementation of them, and a script that runs them across all 83 sites.

How a scrape works today

One entry in sites.toml becomes one crawl. The crawl, the manifest and the ingest are three separate steps, and the ingest decides what to remove.

  • ACrawl order is random. Link extraction returns a set, so on one test site the same settings saved between 45 and 136 pages; seeding from the sitemap steadied it at 207 to 217.
  • BNothing refreshes a single changed page. A normal run adds new pages and leaves changed ones stale; a fresh run re-fetches the whole site to catch them.
  • CRemoval means "the crawl did not reach it." Ingest retires every record that is not in the new run's files, and nothing checks how many that is.

A cleaner full scrape

A full re-scrape is still needed and stays the backstop. What changes is what it downloads: about half of the pages saved in the July manifests were never content.

How an update run differs

Same entry, same scope rules, same fetcher. The change is in the middle: the sitemap's last-modified date decides what to fetch.

What it saves

First all 71 hosts added together, then one host on its own. Both use the July manifests as the starting point and count in-scope sitemap pages.

What happens to one URL

Every URL from the sitemap passes the same gates in the same order. A "no" at any gate stops it; whatever gets through is sorted by comparing dates.

Deleting a page

Today a page is removed because a crawl did not find it. With the sitemap, a page is a removal candidate only if it was listed before and has now disappeared, and a fetch confirms it.

The vocabulary

The taxonomy gives the team names for three things: what a URL is, what a host is, and what state a page is in during an update.

Run it yourself

cd aidocs/feature/scraper-update-mode/rules
../../../../.venv/bin/python -m pytest tests -q
../../../../.venv/bin/python validate_hosts.py

With the real sites.toml and cached manifests, 257 tests pass and 4 skip. With neither of them, as in a clean clone, 76 pass and 26 skip. validate_hosts.py writes report/hosts.csv and report/summary.json, one row per site.
